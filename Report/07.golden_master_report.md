# Golden Master Regression Test Report

## Summary

- 작성일: 2026-05-19
- 대상: C++17 / Google Test / CMake 기반 `TexttestFixture` 출력 회귀 테스트
- 구현 파일:
  - `cpp/test/GoldenMasterTest.cpp`
  - `cpp/test/golden_master/TexttestFixture.ThirtyDays.expected.txt`
  - `cpp/CMakeLists.txt`
  - `.github/workflows/cpp-tests.yml`

## 1. Expected 출력 파일 생성/보관 전략

Golden Master 기준 파일은 테스트 코드와 같은 모듈 경계 안에 보관한다.

- 보관 위치: `cpp/test/golden_master/`
- 파일명: `TexttestFixture.ThirtyDays.expected.txt`
- 기준 범위: 기존 `TexttestFixture` 스타일의 30일치 출력
- 승인 방식: 의도된 동작 변경 시 테스트 실패로 생성되는 `TexttestFixture.ThirtyDays.received.txt`를 검토한 뒤 expected 파일로 반영한다.
- 버전 관리: `*.expected.txt`는 커밋 대상이고, `*.received.txt`는 임시 산출물이므로 커밋하지 않는다.

현재 baseline은 다음 아이템 조합을 포함한다.

- Normal item: `+5 Dexterity Vest`, `Elixir of the Mongoose`
- Special item: `Aged Brie`, `Backstage passes to a TAFKAL80ETC concert`, `Sulfuras, Hand of Ragnaros`
- 신규/확장 item: `Conjured Mana Cake`

## 2. Google Test 파일 비교 테스트 구현

`cpp/test/GoldenMasterTest.cpp`에 출력 기반 회귀 테스트를 추가했다.

- `renderTexttestFixtureOutput(30)`가 `TexttestFixture`와 동일한 형식의 문자열을 만든다.
- `GOLDEN_MASTER_EXPECTED_DIR` 컴파일 정의로 expected 파일 위치를 주입한다.
- expected 파일이 없으면 테스트가 명확히 실패한다.
- expected와 actual이 다르면 actual을 `TexttestFixture.ThirtyDays.received.txt`로 저장해 diff/승인 과정을 돕는다.
- Windows/Unix 체크아웃 차이로 인한 오탐을 막기 위해 expected 파일의 줄바꿈은 비교 전에 LF로 정규화한다.

핵심 테스트:

```cpp
TEST(GoldenMasterTest, TexttestFixtureOutputMatchesThirtyDayBaseline) {
    const std::string actual = renderTexttestFixtureOutput(30);
    const std::string expected = readFile(expectedPath);

    if (expected != actual) {
        writeFile(receivedPath, actual);
    }

    EXPECT_EQ(expected, actual);
}
```

## 3. CMake/CTest 통합

`cpp/CMakeLists.txt`에 별도 실행 파일 `golden_master_test`를 추가했다.

```cmake
add_executable(golden_master_test test/GoldenMasterTest.cpp)
target_link_libraries(golden_master_test gilded_rose GTest::gtest_main)
target_compile_definitions(golden_master_test PRIVATE
    GOLDEN_MASTER_EXPECTED_DIR="${CMAKE_CURRENT_SOURCE_DIR}/test/golden_master"
)

gtest_discover_tests(golden_master_test)
```

이 구성으로 기존 `gilded_rose_test`와 Golden Master 테스트가 모두 `ctest`에서 자동 발견된다.

## 4. CI 자동 실행 구성

GitHub Actions workflow를 `.github/workflows/cpp-tests.yml`에 추가했다.

- 실행 시점: 모든 branch의 `push`, 모든 `pull_request`
- 실행 환경: `ubuntu-latest`
- 단계: checkout -> configure -> build -> ctest
- 테스트 명령: `ctest --test-dir build --output-on-failure`

CI에서 Golden Master 불일치가 발생하면 `golden_master_test`가 실패하므로, 의도하지 않은 출력 회귀를 pull request 단계에서 차단할 수 있다.

## 실행 방법

로컬 PowerShell 기준:

```powershell
cd cpp
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

Golden Master만 실행:

```powershell
ctest --test-dir build -R GoldenMasterTest --output-on-failure
```

baseline 갱신 절차:

1. 의도된 요구사항 변경 후 테스트를 실행한다.
2. 실패 시 생성된 `cpp/test/golden_master/TexttestFixture.ThirtyDays.received.txt`를 검토한다.
3. 출력이 의도와 일치하면 received 내용을 `TexttestFixture.ThirtyDays.expected.txt`에 반영한다.
4. 전체 `ctest`를 다시 실행해 회귀 테스트 통과를 확인한다.
