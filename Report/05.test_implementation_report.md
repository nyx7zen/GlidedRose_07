# Gilded Rose Test Implementation Report

## 1. 작업 목적

C++17, Google Test 기반으로 `GildedRose::updateQuality()`의 아이템 타입별 동작을 검증하는 `TEST_F` 단위 테스트를 작성했다.

대상 아이템은 다음 5종이다.

- Normal
- Aged Brie
- Backstage Pass
- Sulfuras
- Conjured

각 테스트는 Given-When-Then 주석 구조를 사용하고, `EXPECT_EQ`로 `sellIn`과 `quality`를 함께 검증하도록 작성했다.

## 2. 테스트 작성 결과

`cpp/test/GildedRoseTest.cpp`에 공통 fixture `GildedRoseTest`를 추가했다.

Fixture는 단일 아이템을 생성하고 `updateQuality()`를 한 번 실행한 뒤 결과 `Item`을 반환하는 `updateSingleItem()` 헬퍼를 제공한다. 이를 통해 각 테스트가 입력 조건과 기대 결과에 집중할 수 있도록 구성했다.

작성된 테스트 수는 총 26개다.

- Normal: 5개
- Aged Brie: 5개
- Backstage Pass: 6개
- Sulfuras: 5개
- Conjured: 5개

## 3. 경계값 반영

다음 경계 조건을 테스트에 포함했다.

- `quality == 0`: 감소형 아이템이 0 미만으로 내려가지 않는지 검증
- `quality == 50`: 증가형 아이템이 50을 초과하지 않는지 검증
- `sellIn == 0`: 업데이트 후 만료 상태가 되는 당일 규칙 검증
- `sellIn == -1`: 이미 만료된 아이템의 규칙 검증
- `Sulfuras`의 `quality == 80`: 일반 품질 상한 예외 검증

## 4. 구현 보완

`Conjured` 테스트가 요구사항대로 통과하도록 `cpp/src/GildedRose.cpp`를 보완했다.

주요 변경 사항은 다음과 같다.

- 아이템 이름 상수 추가
- `Conjured` 접두어 판별 함수 추가
- `increaseQuality()` / `decreaseQuality()` 헬퍼 추가
- `Sulfuras`는 즉시 `continue`하여 불변 규칙을 명확화
- `Aged Brie`, `Backstage Pass`, Normal, `Conjured`의 품질 변화 규칙을 분기별로 정리
- `std::min`, `std::max` 사용을 위해 `<algorithm>` 명시 include 추가

`Conjured` 판별은 `"Conjured"` 접두어 기반으로 구현했다. 따라서 `"Conjured Mana Cake"` 같은 이름은 `Conjured` 아이템으로 처리된다.

## 5. 검증 결과

다음 명령으로 빌드와 테스트를 실행했다.

```powershell
cmake --build build; if ($LASTEXITCODE -eq 0) { ctest --test-dir build --output-on-failure }
```

실행 결과는 Green이다.

```text
100% tests passed, 0 tests failed out of 26
```

PowerShell 환경에서 `&&` 연산자가 지원되지 않아, 빌드 성공 시에만 `ctest`가 실행되도록 `$LASTEXITCODE` 조건문을 사용했다.

## 6. 결론

요구된 5개 아이템 타입에 대해 타입별 최소 5개 이상의 `TEST_F` 테스트를 작성했고, 품질 및 판매 기한 경계값을 포함해 핵심 비즈니스 규칙을 검증했다.

최종 상태에서 CMake 빌드와 CTest 실행은 모두 성공했다.
